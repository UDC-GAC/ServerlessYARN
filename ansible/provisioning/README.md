# Provisioning directory

This directory contains the main code of the repository, including Ansible automation, configuration, service definitions and helper tooling.

## Structure

- `apps/`: Configuration and scripts of applications to be deployed by the platform
- `collections/`: Ansible custom collections
- `config/`: Configuration files
- `external/`: Git submodules and external dependencies.
- `playbooks/`: Ansible playbooks
- `plugins/`: Ansible custom plugins
- `scripts/`: Helper scripts
- `services/`: Additional services to deploy alongside the platform
- `tasks/`: Ansible tasks
- `templates/`: Template files, including container image definitions
- `tests/`: Tests for specific functionalities
- `tools/`: Utility libraries.
- `vars/`: Shared variables for Ansible's tasks

## Secrets

All secrets used by the platform (CouchDB admin password, CouchDB Erlang cookie and Django secret key) are defined in a single place:

- `vars/secrets.yml`: **insecure** default values, tracked in git. They are publicly known and only suitable for development and testing (e.g., the Vagrant virtual cluster). Do not edit this file to set real secrets.
- `config/secrets.yml`: optional, git-ignored file with your own secrets. Any variable defined here overrides its default value, so you only need to define the secrets you want to change.

Playbooks that need secrets load both files (see `default_secrets` and `user_secrets` in `playbooks/paths.yml`), and every other file (e.g., `templates/services/couchdb/debian_couchdb_conf.dat`, the Django secret key file written to the installation path) gets its value from these variables.

### Using your own secrets (e.g., in production)

1. Create `config/secrets.yml` encrypted with [Ansible Vault](https://docs.ansible.com/ansible/latest/vault_guide/index.html):

   ```bash
   ansible-vault create config/secrets.yml
   ```

   and define the secrets to override:

   ```yaml
   couchdb_admin_pass: '<strong password>'
   couchdb_cookie: '<random string>'
   django_secret_key: '<random key>'
   ```

   If a value contains Jinja2 delimiters (`{{`, `{%` or `{#`), tag it with Ansible's `!unsafe` tag (e.g., `couchdb_admin_pass: !unsafe 'p{{ss'`) so that Ansible uses it literally instead of templating it.

   A new Django key can be generated with `python3 -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"`. Use `ansible-vault edit config/secrets.yml` to modify the file later.

2. Make the Vault password available to every playbook execution, including the ones launched from the web interface, by exporting the path of a file containing it (keep that file outside the repository and readable only by you):

   ```bash
   export ANSIBLE_VAULT_PASSWORD_FILE=~/.serverlessyarn_vault_pass
   ```

   If `config/secrets.yml` is encrypted and no Vault password is provided, playbooks fail instead of silently falling back to the default secrets.

A plain-text `config/secrets.yml` also works (it is git-ignored), but encrypting it is recommended.

Notes:
- Secrets must be set **before** installing the platform: the CouchDB admin password is applied when CouchDB is installed (inside the CouchDB container image when not in virtual mode). To change it afterwards, delete the CouchDB image (`couchdb_container.sif` in the CouchDB installation directory) so that it gets rebuilt with the new password, or, in virtual mode, purge the `couchdb` package so that it gets reinstalled.
- ServerlessContainers (`external/ServerlessContainers`) currently connects to CouchDB with the hard-coded credentials `admin:admin`, so changing `couchdb_admin_pass` will break it until it reads the credentials from its configuration.
